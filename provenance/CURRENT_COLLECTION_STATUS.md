# Current collection method

The user has approved and implemented random-date + circular-time-window sampling for personalfinance with about 150 expected items per month. The main reports are monthly_cluster_status.csv and monthly_cluster_summary.json; the real-time state files are authoritative.

- Media Cloud: all 64 current sample days and 32 collection-months are complete. National 39464 items, local 185150 items. The existing complete months and other complete dates are kept and listed separately; volume indicators come from the existing daily search counts.
- Reddit economy / Economics: each 2015–2024, 3 complete random UTC dates per month, 360 days each; 2017–2024 continues to have priority. The original plan and checkpoints for the two core subreddits are unchanged.
- personalfinance: still the existing 3 random dates per month for 2010-01 to 2026-10, 606 date windows in total. The window length is set from the true monthly total N and the number of observable days D, for about 150 expected items per month; the random start is drawn uniformly on the day's 24-hour circle, and windows crossing midnight are split into two segments at the start and end of the day. Drawn windows are taken in full and are not truncated on reaching 150 items. Completing a window does not mean completing the whole day.
- New design personalfinance_window_design.json, frozen monthly parameters personalfinance_window_month_plans, selection lists monthly_cluster_selections/reddit_personalfinance_window_v1_*. The old complete-day state snapshots and selection lists are kept; the whole-day inventory and the new window sample are kept separate and are not added together or double-counted.
- The report field sample_unit distinguishes UTC_full_day / circular_time_window; personalfinance uses planned/completed_sample_windows, and the complete whole-day count fields are 0. The general planned/completed_sample_dates indicate completion of the sampling unit for the corresponding dates and do not guarantee the whole day is complete.
- The old monthly/half-day main tables and historical design drafts are kept; "not implemented" in personalfinance_sampling_proposal.md is only the status of the historical draft and has been superseded by the actual design authorized by the user this time.
- A single worker per API, the original rate and consecutive-failure caps, exclusion of author fields, keeping retrieved_on, never overwriting raw files, and no hash verification are all maintained. YouTube is not part of this task, and its API is not called or managed.

Inventory priority arrangement: the complete old inventory for personalfinance 2025-01 to 2025-10 can directly generate 30 windows under the new rule, and these have now been moved to the front of the queue; only the true monthly aggregate counts are filled in, with no new body-text downloads. The fixed random dates and window generation rules are unchanged; evidence is in personalfinance_inventory_reuse_audit.json.

The unified count timeout segmentation rule has been implemented: after five timeouts on a full-month aggregate, the month is automatically split into UTC segments of at most 7 days and summed, and the process stops and asks only if a segment fails five times. The personalfinance 2012-11 blockage has been resolved (monthly count 1046), and the worker has continued from the checkpoint; the state files and monthly_cluster_status.csv are authoritative for the specific current progress.
